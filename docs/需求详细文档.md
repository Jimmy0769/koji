# koji 需求详细文档

> 版本：v0.2（需求已确认）
> 日期：2026-11-24
> 平台：Windows 桌面端
> 技术栈：**Tauri 2.x（已确认）**

---

## 1. 项目概述

### 1.1 项目背景

在学习、工作等场景中，人们经常受到手机、网页、聊天软件等干扰，难以长时间保持专注。番茄工作法（Pomodoro Technique）通过"定时专注 + 短暂休息"的方式帮助用户管理注意力。本项目旨在开发一款轻量级的 Windows 桌面专注计时应用，提供倒计时、专注记录、窗口置顶、大小视图切换等功能，帮助用户专注自己的事情并留下专注轨迹。

### 1.2 项目目标

- 提供一个简单、无干扰的倒计时专注工具。
- 帮助用户记录每次专注时段做了什么，形成可回溯的专注记录。
- 支持窗口置顶和迷你小窗模式，让计时器在不遮挡工作的前提下"始终可见"。
- 应用轻量、启动快、占用资源少。

### 1.3 目标用户

- 学生：自习、刷题、背诵时需要计时与记录。
- 上班族：需要番茄式工作法管理任务专注时间。
- 自由职业者 / 远程工作者：自我时间管理。
- 任何希望通过可视化倒计时建立专注习惯的用户。

### 1.4 核心价值

| 价值点 | 说明 |
| --- | --- |
| 轻量专注 | 无社交、无广告、无复杂功能，打开即用 |
| 记录留痕 | 每次中止自动生成记录，可回顾"这段时间做了什么" |
| 始终可见 | 置顶 + 迷你小窗，倒计时不被其他窗口遮挡 |
| 灵活配置 | 倒计时时长可自定义，默认 25 分钟 |

## 2. 名词解释

| 术语 | 说明 |
| --- | --- |
| 正常视图（Normal View） | 功能完整的主窗口，包含倒计时、记录列表、设置等 |
| 小视图（Mini View） | 精简的迷你窗口，仅显示倒计时和核心操作按钮 |
| 计时会话（Session） | 一次从"开始"到"中止/完成"的完整计时过程 |
| 中止（Stop） | 用户在倒计时未结束时主动终止本次会话 |
| 完成（Complete） | 倒计时自然走完归零 |
| 记录（Record） | 一次计时会话结束后生成的一条数据，包含生成时间、持续时长、内容备注 |
| 置顶（Always on Top） | 窗口始终显示在其他应用窗口之上 |

## 3. 总体功能结构

```
koji
├── 正常视图窗口
│   ├── 倒计时模块（设定 / 开始 / 暂停 / 继续 / 中止 / 完成）
│   ├── 记录模块（生成记录 / 填写内容 / 查看记录列表 / 记录详情）
│   ├── 设置模块（默认倒计时时长）
│   ├── 视图切换（→ 小视图）
│   ├── 窗口置顶开关
│   └── 窗口拖动
├── 小视图窗口
│   ├── 倒计时显示
│   ├── 开始 / 暂停 / 继续 / 中止（中止时可填写记录）
│   ├── 视图切换（→ 正常视图）
│   ├── 窗口置顶开关
│   └── 窗口拖动
└── 公共能力
    ├── 计时引擎（两种视图共用同一计时状态）
    ├── 本地数据存储（记录 + 设置）
    └── 系统托盘（建议项）
```

**关键设计原则：正常视图与小视图是同一个应用的两种窗口形态，共享同一份计时状态与数据。切换视图时，正在进行的倒计时不中断、不重置。**

## 4. 功能需求详述

### 4.1 正常视图窗口

#### FR-1 倒计时功能

**功能编号：FR-1-01 设定时长**

- 用户可在未开始状态下设定本次倒计时时长。
- 默认时长为 **25 分钟**（可在设置中修改默认值）。
- 提供快捷时长按钮（建议）：15 / 25 / 45 / 60 分钟，点击即设定。
- 支持自定义输入：以分钟为单位，范围 **1 ~ 240 分钟**（范围可配置）。
- 倒计时显示格式：`MM:SS`（超过 99 分钟时显示 `HH:MM:SS`）。

**功能编号：FR-1-02 开始**

- 点击"开始"按钮后，按当前设定时长启动倒计时。
- 开始后，时长设定控件变为不可编辑状态。
- 按钮状态切换为"暂停"与"中止"。
- （建议）开始后窗口标题栏或界面显示当前会话状态标识。

**功能编号：FR-1-03 暂停 / 继续**

- 点击"暂停"后，倒计时冻结，已计时长保留。
- 暂停状态下按钮显示"继续"，点击后从暂停点恢复倒计时。
- 暂停期间"中止"按钮仍然可用。
- 暂停时长不计入记录的"持续时长"（持续时长 = 实际专注时间，见 FR-2-01）。

**功能编号：FR-1-04 中止**

- **5 分钟保护规则：会话开始不足 5 分钟即中止的，不生成记录**，也不弹出记录填写框，仅提示"本次专注不足 5 分钟，未生成记录"（阈值固定 5 分钟）。
- 满足 5 分钟规则时，点击"中止"后弹出**记录填写对话框**：
  - 显示本次会话的生成时间与持续时长（只读）。
  - 提供多行文本框，供用户填写"这段时间做了什么"，**非必填**。
  - 提供"保存记录"与"放弃记录"两个操作：
    - **保存记录**：生成一条新记录（内容可为空）。
    - **放弃记录**：**完全不生成任何记录**，直接回到空闲状态。
- 保存或放弃后，计时器均回到初始空闲状态。
- 中止操作建议增加二次确认（如气泡确认"确定要中止本次专注吗？"），防止误触。

**功能编号：FR-1-05 倒计时完成**

- 倒计时归零时：
  - 播放提示音（可开关，建议项）。
  - 弹出系统通知 / 窗口闪烁提醒（建议项）。
  - 弹出与中止相同的**记录填写对话框**，行为与 FR-1-04 一致：
    - 点击"保存记录"生成一条记录（finishType = completed，内容非必填，可预填"完成了一个番茄钟"）；
    - 点击"放弃记录"则不生成记录。
  - 完成场景**不受 5 分钟保护规则限制**（即使设定时长小于 5 分钟并完整走完，也弹出填写框）。
- 完成后计时器回到初始空闲状态，可立即开始下一轮。

#### FR-2 记录功能

**功能编号：FR-2-01 记录生成规则**

- 触发时机（均需在弹窗中点击"保存记录"才真正生成，点击"放弃记录"则不生成任何记录）：
  1. 用户主动**中止**会话，且本次会话已计时 **≥ 5 分钟**（不足 5 分钟的中止不生成记录、不弹填写框）；
  2. 倒计时**自然完成**（不受 5 分钟限制）。
- 记录字段：

| 字段 | 类型 | 说明 | 是否必填 |
| --- | --- | --- | --- |
| id | string | 唯一标识（UUID） | 系统生成 |
| createdAt | datetime | 记录生成时间（会话结束时刻） | 系统生成 |
| startedAt | datetime | 会话开始时刻 | 系统生成 |
| duration | int（秒） | 持续时长 = 实际计时时间（不含暂停） | 系统生成 |
| plannedDuration | int（秒） | 计划时长（设定的倒计时长度） | 系统生成 |
| content | string | 用户填写的内容备注 | 否（可为空） |
| finishType | enum | 结束方式：completed（完成）/ aborted（中止） | 系统生成 |

- **边界规则（5 分钟保护）：** 会话开始不足 **5 分钟**即被中止的，**不生成记录**，也不弹出填写框（仅轻提示）。该规则仅约束"中止"场景；倒计时自然完成不受此限制。

**功能编号：FR-2-02 记录列表查看**

- 正常视图中展示记录列表，按生成时间**倒序**排列（最新在上）。
- 每条记录展示：
  - 生成时间：`YYYY-MM-DD HH:mm`
  - 持续时长：友好格式，如 `25 分钟`、`1 小时 5 分钟`
  - 记录内容：单行截断显示，hover 或点击可查看完整内容。
  - 结束方式标识：完成 / 中止（不同颜色或图标区分）。
- 支持按日期分组显示（今天 / 昨天 / 更早）。
- 支持删除单条记录（需二次确认）。
- （建议项）支持编辑已保存记录的 content 内容。
- （建议项）支持按关键词搜索记录。

**功能编号：FR-2-03 数据持久化**

- 所有记录保存在本地，应用重启后不丢失。
- 存储方案建议：本地 JSON 文件 或 SQLite 数据库（见第 7 节技术建议）。
- 存储位置建议：`%APPDATA%/koji/`。

#### FR-3 时长配置

**功能编号：FR-3-01 默认时长设置**

- 设置项：默认倒计时时长，默认值 **25 分钟**。
- 修改后，对**下一次**新会话生效；不影响正在进行的会话。
- 应用启动时，倒计时初始值 = 用户配置的默认时长。
- 设置项持久化保存。
- （建议项）其他可配置：提示音开关、提示音选择、中止二次确认开关。（5 分钟记录保护阈值为固定值，不开放配置。）

#### FR-4 视图切换

**功能编号：FR-4-01 切换到小视图**

- 正常视图提供"切换到小视图"按钮（图标建议：缩小/画中画样式）。
- 切换后：正常视图窗口关闭（隐藏），小视图窗口出现。
- **计时状态无缝迁移**：正在进行的倒计时、已暂停状态、剩余时间完整保留。
- 小视图窗口出现在原正常视图窗口附近（建议：以原窗口中心为基准，或记忆上次小视图位置）。

**功能编号：FR-4-02 切换回正常视图**

- 小视图提供"切换到正常视图"按钮。
- 切换规则与 FR-4-01 对称，计时状态同样无缝迁移。
- 正常视图窗口恢复至上次关闭前的位置与大小（记忆窗口位置）。

#### FR-5 窗口置顶

**功能编号：FR-5-01 置顶开关（正常视图）**

- 正常视图提供"置顶"切换按钮（图标建议：图钉 📌）。
- 开启后窗口始终显示在其他非置顶应用窗口之上（`HWND_TOPMOST`）。
- 关闭后恢复正常层级。
- 置顶状态在界面上有明显视觉反馈（如图钉图标高亮）。
- 正常视图的置顶状态与小视图**相互独立**（已确认 Q4）：各自维护、各自持久化，切换视图互不影响；正常视图默认**不置顶**。

#### FR-6 窗口拖动

**功能编号：FR-6-01 拖动（正常视图）**

- 用户可按住标题栏（或自定义拖拽区域）拖动窗口至屏幕任意位置。
- 窗口位置记忆：应用退出时保存位置，下次启动恢复（建议项）。
- （建议）窗口不可拖出可视屏幕区域之外，防止"丢失窗口"。

#### FR-7 其他窗口行为（建议补充）

- **最小化到托盘**：点击关闭按钮时最小化到系统托盘而非退出（计时不中断），托盘菜单提供"显示主窗口 / 退出"。
- **单实例运行**：重复启动时激活已有窗口，而不是打开第二个实例。
- **计时不随窗口隐藏中断**：最小化 / 托盘 / 切换视图期间，计时引擎持续运行。

### 4.2 小视图窗口

#### FR-8 小视图布局与显示

**功能编号：FR-8-01 窗口形态**

- 窗口尺寸建议：约 **220 × 90 px**（无边框窗口，尺寸可微调）。
- 无边框设计（frameless），界面元素极简。
- 置顶悬浮于桌面之上，不遮挡用户主要工作区域。

**功能编号：FR-8-02 倒计时显示**

- 大字显示剩余时间 `MM:SS`，为窗口视觉核心。
- 以颜色 / 状态点区分计时状态（建议）：
  - 空闲：灰色
  - 运行中：绿色（或主题色）
  - 暂停：黄色 / 闪烁
- （建议项）以细进度条或环形进度显示剩余比例。

**功能编号：FR-8-03 操作按钮**

- 按钮数量最少化，横向排列于时间下方：
  - 空闲态：`开始`
  - 运行态：`暂停`、`中止`
  - 暂停态：`继续`、`中止`
- 点击"中止"时（会话已计时 ≥ 5 分钟）：弹出**紧凑的记录填写小弹窗**：
  - 显示生成时间与持续时长。
  - 单行 / 少量多行输入框填写内容（非必填）。
  - `保存` / `放弃` 按钮：保存生成记录，放弃则不生成任何记录（与正常视图规则一致）。
  - 弹窗同样遵循小视图当前的置顶设置。
- 会话不足 5 分钟时点击"中止"：不弹填写框、不生成记录，轻提示后直接回到空闲状态。
- （建议）小视图不提供记录列表查看，保持简洁；如需查看记录，切回正常视图。

#### FR-9 小视图置顶

**功能编号：FR-9-01 置顶开关（小视图）**

- 小视图提供小型置顶切换按钮（图钉图标），位于窗口角落。
- 开关逻辑与 FR-5-01 相同，状态持久化保存，重启后恢复。
- 小视图的置顶状态与正常视图**相互独立**（已确认 Q4），小视图默认**开启置顶**。

#### FR-10 小视图拖动

**功能编号：FR-10-01 拖动**

- 由于无边框，**按住窗口任意空白区域即可拖动**。
- 小视图位置记忆：退出时保存，下次以小视图形态启动时恢复（建议项）。
- 双击空白区域切换视图（快捷操作，建议项）。

## 5. 计时状态机

两种视图共用同一状态机：

```
                 ┌──────────────────────────────┐
                 ▼                              │
  ┌────────┐  开始   ┌────────┐  暂停   ┌────────┐ │
  │  空闲   │──────▶│  运行中  │──────▶│  已暂停  │ │
  │  Idle  │       │Running │◀──────│ Paused │ │
  └────────┘       └────────┘  继续   └────────┘ │
      ▲                 │                   │    │
      │               归零                 中止   │
      │            (完成 Complete)      (Abort)   │
      │                 │                   │    │
      │                 ▼                   ▼    │
      │           ┌──────────┐        ┌─────────┐ │
      │           │ 完成弹窗   │        │中止弹窗   │ │
      │           │(可填记录)  │        │(≥5分钟时) │ │
      │           └──────────┘        └─────────┘ │
      │                 │                   │    │
      └─────────────────┴───── 保存/放弃 ─────┘
              （保存→生成记录；放弃→不生成记录；均回到空闲）
```

**状态迁移说明：**

| 当前状态 | 触发 | 目标状态 | 副作用 |
| --- | --- | --- | --- |
| 空闲 | 开始 | 运行中 | 记录 startedAt，锁定时长设置 |
| 运行中 | 暂停 | 已暂停 | 冻结剩余时间，记录暂停时刻 |
| 运行中 | 归零 | 空闲 | 弹出完成提示与填写框，点击"保存"才生成记录（完成类型） |
| 运行中 | 中止 | 空闲 | 已计时 ≥ 5 分钟：弹出中止填写框，点击"保存"才生成记录（中止类型）；不足 5 分钟：不弹框、不生成记录 |
| 已暂停 | 继续 | 运行中 | 从暂停点恢复 |
| 已暂停 | 中止 | 空闲 | 同"运行中→中止" |

**持续时长计算：** `duration = 归零或中止时刻 − startedAt − 累计暂停时长`（即只统计真正计时的时间）。

**视图切换不改变状态机状态**，仅更换渲染窗口。

### 6.2 中止记录填写弹窗

```
┌──────────────────────────────┐
│  本次专注已结束                  │
│                              │

│  持续时长：13 分钟（计划 25 分钟）│
```

## 7. 非功能需求

| 编号 | 类别 | 需求描述 |
| --- | --- | --- |
| NFR-1 | 性能 | 应用冷启动时间 ≤ 3 秒；计时精度误差 ≤ 1 秒/小时 |
| NFR-2 | 资源占用 | 常驻内存建议 ≤ 150 MB；空闲 CPU 占用接近 0% |
| NFR-3 | 可靠性 | 应用异常退出后重启，已有记录不丢失；计时中真正退出需弹确认框（保存记录并退出 / 丢弃并退出） |
| NFR-4 | 兼容性 | 支持 Windows 10（1809+）/ Windows 11，x64 |
| NFR-5 | 易用性 | 主操作（开始/暂停/中止）无需菜单深入，一键可达 |
| NFR-6 | 数据安全 | 记录仅存储在本地，不上传任何服务器，无联网行为 |
| NFR-7 | 计时准确性 | 计时基于系统单调时钟（monotonic clock），不受用户修改系统时间影响（建议实现方式） |
| NFR-8 | 电源场景 | 系统睡眠/休眠时间计入倒计时流逝时间，唤醒后若超时视为完成 |
| NFR-9 | 界面语言 | 简体中文（界面文案预留国际化能力，建议项） |

## 8. 技术方案（已确认：Tauri 2.x）

选型对比留档如下：

| 方案 | 优点 | 缺点 | 适配度 |
| --- | --- | --- | --- |
| **Tauri 2.x（Rust + Web 前端）** | 安装包极小（~5 MB）、内存占用低、原生置顶/无边框/托盘 API 完善、单实例插件现成 | 需要 Rust 工具链，Windows 依赖 WebView2 | ★★★★★ 推荐 |
| **Electron** | 生态最成熟、开发效率高、无边框/置顶/托盘支持完善 | 安装包 80 MB+、内存占用高（与"轻量"目标冲突） | ★★★★ |
| **WPF / WinUI 3（C#）** | Windows 原生体验最好、资源占用低 | 仅限 Windows、前端生态相对小 | ★★★★ |
| **PyQt / PySide6** | Python 开发快、跨平台 | 打包体积大、原生观感一般 | ★★★ |
| **Flutter Desktop** | UI 一致性好、动画流畅 | Windows 桌面生态尚在完善、置顶等需插件 | ★★★ |

**已确认采用：Tauri 2.x。** 理由：与本应用"轻量、常驻桌面、小窗置顶"的定位高度契合；置顶（always-on-top）、无边框（decorations: false）、拖拽（data-tauri-drag-region）、系统托盘、单实例、本地存储（tauri-plugin-store 或 SQLite 插件）均有官方支持。

## 10. 边界情况与异常处理

| 场景 | 处理策略（建议） |
| --- | --- |
| 计时中应用被关闭 | 若最小化到托盘：计时继续；若真正退出（托盘菜单→退出）：弹出确认框，选择"保存记录并退出 / 丢弃并退出"（Q5 已确认） |
| 计时中切换视图 | 状态无缝迁移，计时不受影响 |
| 计时中系统睡眠/休眠 | 睡眠时间**计入**流逝时间（按真实时间计算）；唤醒后若已超时则视为完成并弹出完成填写框（Q6 已确认） |
| 不足 5 分钟即中止 | 不弹填写框、不生成记录，轻提示"本次专注不足 5 分钟，未生成记录"后回到空闲状态 |
| 中止/完成弹窗中点击"放弃" | 不生成任何记录，直接回到空闲状态（Q1 已确认） |
| 计时中修改系统时间 | 使用单调时钟，倒计时不受影响；记录的 createdAt 使用系统时间 |
| 剩余时间归零瞬间用户点了中止 | 以先触发的事件为准，归零优先判定为"完成" |
| 记录内容超长 | 限制 content 最大长度（建议 500 字符），超出截断并提示 |
| 多显示器 / 分辨率变化 | 记忆的窗口位置超出当前屏幕范围时，回退到屏幕中心 |
| 数据文件损坏 | 启动时校验，损坏则备份原文件并以空数据启动，提示用户 |

## 14. 验收标准（v1.0）

1. 正常视图可设定时长（默认 25 分钟）并完成开始 → 暂停 → 继续 → 中止全流程，计时准确。
2. 中止（已计时 ≥ 5 分钟）或倒计时完成后弹出记录填写框；点击"保存记录"才生成记录，点击"放弃"不生成任何记录；不足 5 分钟的中止不弹框、不生成记录。记录包含生成时间、持续时长（不含暂停时间）、内容（可空）。
3. 记录列表按时间倒序展示，可查看完整内容、可删除。
4. 正常视图 ↔ 小视图切换时，计时状态无缝保留。
5. 两种视图均可独立拖动；置顶开关即时生效，且两视图的置顶状态相互独立、各自记忆。
6. 小视图以极简形态显示倒计时与开始/暂停/继续/中止操作，中止时可填写记录。
7. 记录与设置本地持久化，重启应用后数据完整。
8. 应用重启 / 切换视图 / 最小化期间，后台计时不中断、不走时异常。
