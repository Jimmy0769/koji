设计概览

两种窗口形态共享同一份计时状态与数据；切换视图时正在进行的倒计时不中断、不重置。以下原型均按文档中的建议尺寸绘制。

A正常视图 Normal View

  • 倒计时主区（环形进度 + MM:SS 大字）
  • 快捷时长 15 / 25 / 45 / 60 + 自定义
  • 开始 / 暂停 / 继续 / 中止 操作区
  • 记录列表（今日 / 昨天 / 更早 分组）
  • 标题栏：置顶 · 切小窗 切换 · 最小化 · 关闭

B小视图 Mini View

  • 无边框，220 × 90 px，默认置顶
  • 状态色点 + 大字倒计时 + 细进度条
  • 按钮最少化：开始 / 暂停 / 继续 / 中止
  • 按住任意空白区域拖动
  • 双击空白区切换回正常视图

C状态与配色

  • ● 空闲 Idle — 灰色
  • ● 运行中 Running — 绿色
  • ● 已暂停 Paused — 黄色 / 闪烁
  • 置顶生效时窗口描边高亮（蓝色描边）
  • 完成 绿 / 中止 橙 区分结束方式

D记录生成流程

  • 中止且已计时 ≥ 5 分钟 → 弹填写框
  • 倒计时自然完成 → 弹填写框（无 5 分钟限制）
  • 弹窗点保存才生成记录；点放弃不生成任何记录
  • 不足 5 分钟中止 → 不弹框、不生成，仅轻提示
  • 保存 / 放弃后均回到空闲状态

计时状态机

两种视图共用同一状态机；视图切换只更换渲染窗口，不改变任何状态。持续时长 = 归零或中止时刻 − startedAt − 累计暂停时长。

关键规则速查

以下规则直接决定 UI 文案与按钮可用性，实现时需逐条核对。

5 分钟保护
会话开始不足 300 秒 即被中止的，不生成记录、不弹出填写框，仅轻提示「本次专注不足 5 分钟，未生成记录」并回到空闲状态。该阈值固定，不开放配置。此规则只约束「中止」场景。
完成不受限
倒计时自然归零时，即使设定时长小于 5 分钟并完整走完，也照常弹出填写框；点击「保存记录」生成 finishType = completed 的记录。
保存 / 放弃
弹窗中「保存记录」才真正生成一条记录（content 可为空）；「放弃」完全不生成任何记录。两种操作结束后计时器均回到初始空闲状态。
持续时长
duration = 归零或中止时刻 − startedAt − 累计暂停时长，即只统计真正计时的时间，暂停时长不计入。
置顶独立
正常视图与小视图的置顶状态各自维护、各自持久化，切换视图互不影响。正常视图默认不置顶，小视图默认置顶。
视图切换
切换视图时正在进行的倒计时、暂停状态、剩余时间完整保留，计时不中断、不重置；新窗口出现在原窗口附近。
边界判定
剩余时间归零瞬间用户点了中止：以先触发的事件为准，归零优先判定为「完成」。
睡眠休眠
系统睡眠 / 休眠时间计入倒计时流逝时间（按真实时间计算）；唤醒后若已超时则视为完成并弹出完成填写框。计时基于单调时钟，不受用户修改系统时间影响。
